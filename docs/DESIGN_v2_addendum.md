## 11. ダークモード基調への配色刷新

### 11.1 方針
- v1では「ライトモードをデフォルト、ダークはOS設定追従の`@media (prefers-color-scheme: dark)`」という位置づけだった。v2では**ダークモードをデフォルト（無指定時の初期表示）とし、ライトモードは任意切り替え可能な副次モード**に格下げする。
- 実装方針: `<html data-theme="dark">`を初期値としてHTMLに直書きし、`:root`直下の変数はダーク配色を基準値とする。ライト配色は`[data-theme="light"]`を明示的に付けた場合のみ適用する（`prefers-color-scheme`への追従は行わない、またはOS設定がlightの場合のみ初回に軽く追従して以後は手動トグルを優先、程度の扱いでよい）。
- 「装飾を減らし可読性重視」の観点から、以下をv1から変更する。
  - カードの`border-radius`: `12px → 8px`（角丸を控えめに）
  - カードに影（box-shadow）は使わない（v1も未使用だったため変更なし、明記のみ）
  - ボタンのグラデーション・強い色面は使わず、**塗り面は最小限＋枠線・テキストで区別**するフラットデザインへ寄せる（特に4択ボタンは「選択されるまでは全て同じ地味なニュートラル色」とし、正誤判定後にのみ色を付ける＝色の情報量を「今まさに必要な瞬間」だけに絞る）
  - タイマー警告の点滅アニメーションは廃止し、色変化のみ（`prefers-reduced-motion`分岐が不要になり実装がシンプルになる副次効果あり。どうしても動きを付けたい場合は透明度変化ではなく1回だけの軽いフラッシュに留める）

- A〜Dのラベルは表示用の便宜的なもの（内部的には`choices`配列のindex 0〜3と対応、選択肢の並び順は運営者がデータ側で自由に決めた順で表示＝自動シャッフルはデフォルトでは行わない。将来的にシャッフルしたい場合は表示時のみindexをシャッフルし、`correctIndex`もシャッフル後の対応表で引き直す実装を推奨・本要望の必須スコープ外）。
- 4択ボタンは縦積み1列固定（横幅を最大限使い長い選択肢文でも折り返しやすくするため。横2×2グリッドは選択肢文が長い日本語では読みにくくなるため不採用）。
- △ボタンは4択と視覚的に離す（余白を広めに取る）ことで「これは正誤の選択肢ではなく手動採点の補助操作である」ことを明確化する。

### 12.4 △ボタン押下時

```
│  ┌────────────────────────────────────────┐  │
```

- サウンドは正解/不正解のような明確な二択ではないため、△専用の軽い中立音（例: 短い「ポン」1音、後述13章）を鳴らすか、無音のままでもよい（本要望では明記なし、実装時判断でよい旨を注記）。

## 13. データ構造案（運営者が後から編集しやすい形）

```js
// quizData: 運営者(研修担当)が問題を追加・編集する唯一の場所。
// 各問題は以下の形式に従う。choicesは必ず4件、correctIndexは0〜3で
// choices配列内の「正解の位置」を指す。
const quizData = [
  {
    // Q1
    question: "「メタクエスト3」は何年何月に発売された？",
    choices: [
      "2023年10月",   // index 0 ← これが正解
      "2022年6月",     // index 1 (ひっかけ: 旧モデル発売年と混同させる)
      "2024年1月",     // index 2 (ひっかけ: 翌年と誤認させる)
      "2021年11月"     // index 3 (ひっかけ: Meta Quest 2の発売時期)
    ],
    correctIndex: 0,
    ambiguousScore: 0.5 // △ボタン押下時に付与する点数。通常は全問0.5固定でよいが、
                        // 問題によって重みを変えたい場合はここを個別編集する
  },
  {
    // Q2
    question: "メタクエスト3（512GB）の価格はいくら？",
    choices: [
      "82,500円",      // index 0 (ひっかけ: 128GBモデルの価格帯)
      "96,800円",      // index 1 ← 正解
      "74,800円",      // index 2 (ひっかけ: Quest 2の価格帯)
      "112,000円"      // index 3 (ひっかけ: それらしい高め価格)
    ],
    correctIndex: 1,
    ambiguousScore: 0.5
  },

  // --- 以下同様に全17問分を追加 ---
  // 【運営者向け編集メモ】
  // ・choicesの並び順を変えても correctIndex を必ず合わせて修正すること。
  // ・ひっかけ選択肢は「もっともらしい誤答」を意識する
  //   （明らかにデタラメな選択肢は4択として機能しないため避ける）。
  // ・question / choices の文字列はそのままHTMLエスケープして表示されるため、
  //   HTMLタグの直接記述は不要（&や<等の記号もそのまま書いてよい）。
  // ・問題を追加・削除した場合、進捗表示や満点計算は quizData.length を
  //   参照する設計のため自動で追従する（v1の9章の前提を踏襲）。
];
```

- v1の`{ question, answer }`（自由回答用）から`{ question, choices[4], correctIndex, ambiguousScore }`へ完全に置き換える。旧`answer`（正解の文字列）は`choices[correctIndex]`が兼ねるため別途保持不要（ただし復習画面での「正解」表示は`choices[correctIndex]`を参照すればよい）。
- コメントで「ひっかけ選択肢の作り方の指針」と「編集時の注意（correctIndexとの整合）」を明記することで、非エンジニアの運営者でも安全に追記できる形にした。

## 14. 状態遷移の変更点

### 14.1 内部状態（v2版）

```
appState:
  "start"     … スタート画面
  "quiz"      … 4択+△ボタン表示中、未回答
  "feedback"  … 選択直後、正誤色表示＋サウンド再生＋自動遷移待ち（新設、v1の"answer"を置換）
  "result"    … 結果画面
  "review"    … 間違い復習画面（新設）

currentIndex: 0..16
timeRemaining: 480 → 0
records[]: { index, question, choices, correctIndex,
             selectedIndex: number|null,   // 4択のどれを押したか。△の場合はnull
             mode: "auto" | "ambiguous" | "timeout", // 採点経路の記録（復習画面での表示分岐に使用）
             score: 0 | 0.5 | 1 | null,
             answered: boolean }
totalScore, correctRatePct(live): 都度再計算してヘッダーに反映
```

### 14.2 イベントと遷移（v1の4.2を置き換え）

| 現在状態 | イベント | 遷移先 | 副作用 |
|---------|---------|--------|--------|
| start | 「はじめる」クリック | quiz(index=0) | タイマー開始、records初期化 |
| quiz | 4択ボタンクリック(選んだindex) | feedback | 即時採点: `selectedIndex===correctIndex ? score=1 : score=0`, `mode="auto"`, 正誤サウンド再生、選択肢の色を確定表示、4択ボタンを全て無効化 |
| quiz | △ボタンクリック | feedback | `score=ambiguousScore(0.5)`, `mode="ambiguous"`, `selectedIndex=null`, 中立サウンド(または無音)、4択ボタンを全て無効化 |
| feedback | 自動タイマー経過（既定1.2〜1.5秒） | quiz(index+1) または result | records確定は選択/△クリック時点で完了済み。ここでは画面遷移のみ |
| quiz/feedback | timeRemaining が 0 に到達 | result | v1同様、未回答分は`score=0, mode="timeout", answered=false` |
| result | 「間違えた問題を復習する」クリック | review | `records`から`score < 1`（0または0.5）のものを抽出して一覧生成 |
| review | 「間違えた問題だけ再挑戦」クリック | quiz（再挑戦用の縮小セッション、後述） | 誤答だった問題のみを新しい出題キューとして再構成、タイマーは再起動しない（当初の8分は使い切っている想定のため。任意で新規タイマーを設けてもよいが必須要件ではない） |
| review | 「結果画面に戻る」クリック | result | 状態変化なし、表示切替のみ |

### 14.3 feedback状態の自動遷移タイミング
- 選択肢クリックから次画面遷移までの待ち時間: **1200ms〜1500ms**を推奨（正誤の色とサウンドを認識するのに十分、かつテンポを損なわない長さ）。
- 待機中に誤って連打されないよう、4択・△ボタンは`feedback`状態突入と同時に全て`disabled`にする（v1の採点3ボタンの連打防止方針を踏襲）。
- 待機を短縮したいユーザー向けに、任意で「次へ ▶」ボタンを画面下部に出し、クリックで即座に次へ進めるようにしてもよい（必須ではないが、8分の制限時間内により多くの問題に触れたいユーザーへの配慮として実装しやすいので推奨）。

### 14.4 再挑戦セッション（review→quiz）の扱い
- 再挑戦は「誤答だった問題のみを対象にした別セッション」として扱い、**元の`records`（人事評価用の結果）は上書きしない**。再挑戦の結果は復習用の別集計（例: `reviewRecords[]`）として保持し、結果画面の正式スコアには影響させない設計とする（人事評価記録の改ざん防止の観点からもこの分離は重要）。
- 再挑戦セッション終了後は「復習結果」画面（簡易: 何問中何問正解したか）を出し、「結果画面に戻る」導線を用意する。

## 15. サウンド実装方針（Web Audio API）

外部音声ファイルは使用せず、`AudioContext` + `OscillatorNode` + `GainNode`のみで生成する。

### 15.1 共通実装方針
- `AudioContext`は初回のユーザー操作（スタート画面の「はじめる」ボタンクリック、または最初の選択肢クリック）内で生成・resumeする（ブラウザの自動再生ポリシー対策。ページロード時点での生成は避ける）。
- 音量はクリック音のような不快なノイズを避けるため、`GainNode`で**アタック(立ち上がり) 5〜10ms、ディケイ(減衰) 末尾50〜80ms**のエンベロープを必ずかける（`gain.linearRampToValueAtTime`等）。矩形波(`square`)を使う場合は特に減衰処理がないとプチノイズが目立つため必須。
- 全体音量は控えめ（`gain`ピーク値 0.15〜0.25程度、0〜1スケール）とし、研修・会議室等の環境での再生を想定してうるさくなりすぎないようにする。
- ミュート/音量オフの設定は本要望に必須ではないが、ヘッダー右上等に🔊/🔇トグルを置く拡張余地として触れておく（スコープ外・任意）。

### 15.2 正解音（明るく短い上昇音）
- 波形: `sine`（柔らかい音色）
- 周波数: 2音を短く連続で鳴らす「上昇アルペジオ」推奨
  - 1音目: 660Hz（E5付近）を 0〜90ms
  - 2音目: 880Hz（A5付近）を 90〜200ms
  - もしくは`OscillatorNode.frequency.exponentialRampToValueAtTime`で660Hz→990Hzへ150ms程度で滑らかに上昇させる単音でも可（実装はどちらでもよい旨を明記）
- 全体長: 約150〜220ms
- ゲイン: ピーク0.2、アタック5ms、200ms地点までにゼロへディケイ

### 15.3 不正解音（低く短いブザー音）
- 波形: `square`または`sawtooth`（ブザーらしい硬めの音色）
- 周波数: 180Hz固定、または200Hz→150Hzへわずかに下降
- 全体長: 約250〜350ms。「ブー」という単発の短いブザーで、正解音より心持ち長めにして違いを明確にする
- 任意で2回の短いパルス（120ms音＋40ms無音＋120ms音）にすると「不正解」らしさが増すが、単発でも要件は満たす
- ゲイン: ピーク0.18、アタック5ms、末尾80msでディケイ

### 15.4 △（曖昧・一部正解）音（任意）
- 正解/不正解のどちらでもない中立トーンとして、`sine`波形・440Hz（A4）付近を120ms程度、フラットに近いエンベロープで1音だけ鳴らす案を推奨（「淡々と記録された」印象の音）。鳴らさない（無音）という選択も許容する。

### 15.5 実装コード方針（擬似コード、参考記載のみ）
```js
function beep({ freqStart, freqEnd, duration, type, peakGain }) {
  const ctx = getAudioContext(); // 初回生成・resumeはユーザー操作時に済ませておく
  const osc = ctx.createOscillator();
  const gain = ctx.createGain();
  osc.type = type;
  osc.frequency.setValueAtTime(freqStart, ctx.currentTime);
  if (freqEnd && freqEnd !== freqStart) {
    osc.frequency.exponentialRampToValueAtTime(freqEnd, ctx.currentTime + duration / 1000);
  }
  gain.gain.setValueAtTime(0, ctx.currentTime);
  gain.gain.linearRampToValueAtTime(peakGain, ctx.currentTime + 0.008); // attack
  gain.gain.linearRampToValueAtTime(0, ctx.currentTime + duration / 1000); // decay
  osc.connect(gain).connect(ctx.destination);
  osc.start();
  osc.stop(ctx.currentTime + duration / 1000 + 0.02);
}

// 正解: beep({ freqStart: 660, freqEnd: 990, duration: 180, type: "sine", peakGain: 0.2 });
// 不正解: beep({ freqStart: 180, freqEnd: 150, duration: 300, type: "square", peakGain: 0.18 });
```
※上記はデザイン仕様としての「方向性の例示」であり、実装担当が数値を微調整することは許容する。

## 16. ライブ正答率表示の配置

### 16.1 配置場所
- クイズ画面ヘッダー（`.quiz-header`相当）内、受験者名とタイマーの間に追加する（12.1のワイヤーフレーム参照）。3項目が横並びになるため、狭幅画面では`flex-wrap`で折り返す（v1のヘッダーが既に`flex-wrap: wrap`のため踏襲）。
- 表示形式: `正答率(現在) 76%` のようにラベル＋数値。ラベルは「現在」であることを明示し、結果画面の最終正答率と混同されないようにする。

### 16.2 計算式
```
answeredCount = records のうち answered===true の件数（現在の問題含む、feedback確定後に+1）
scoredSum = records のうち answered===true な score の合計
liveRatePct = answeredCount === 0
  ? null   // 1問も回答していない状態。"ー%" または非表示にする
  : round(scoredSum / answeredCount × 100)  // 小数点なしの整数%表示（結果画面は小数点1桁だが、
                                              // ヘッダーは簡潔さ優先で整数%にする方針を推奨）
```
- 分母は「全17問」ではなく「**回答済み問題数**」であることに注意（分母を全体固定にすると序盤は正答率が意味を持たない小さな値になり続けるため、進行中の実感値としては回答済み数で割るほうが有用）。
- 更新タイミング: `feedback`状態への遷移時（採点確定時）に再計算・再描画する。タイマーのように毎秒更新する必要はない。
- 1問も回答していない開始直後は「正答率 ー%」のようにダッシュ表示にし、0%と区別する（0%だと「1問回答して全部不正解」と誤解されるため）。

## 17. 復習画面（review）ワイヤーフレーム

結果画面（Result）に「間違えた問題を復習する」ボタンを追加し、押下でreview画面へ遷移する。

### 17.1 結果画面への追加要素

```
┌──────────────────────────────────────────────┐
│         研修クイズ 結果レポート                   │
│  ...(v1の内容と同様: 氏名/実施日/スコア/内訳表)... │
│                                                │
│        ┌───────────────────┐                 │
│        │ 📖 間違えた問題を復習する │  ← 新規追加   │

│        │  🖨 印刷する      │                     │
```

- 全問正解（0点・0.5点の問題が1件もない）の場合は、このボタンを「🎉 全問正解でした！復習の必要はありません」という祝福メッセージに差し替え、ボタン自体は非表示にする。

### 17.2 復習画面 本体

```

│  ─────────────────────────────────────────── │

│  │ 正解:        A  ヘッドマウントディスプレイと│  │

│  └────────────────────────────────────────┘  │
│                                                │
│  ┌────────────────────────────────────────┐  │
│  │ Q12. ...(以下同様に間違えた問題を全件列挙)  │  │
│  └────────────────────────────────────────┘  │
│                                                │

```

- 一覧は`records`から`score < 1`（0または0.5、および未回答/タイムアウトも含む）の項目のみを、元の出題順（No順）で抽出して表示する。
- `mode==="ambiguous"`（△で確定した問題）は「あなたの回答」欄に選択肢は出さず「△ 曖昧・一部正解として記録」の固定文言を表示する（そもそも4択のどれを口頭で答えたかシステム側は把握していないため）。
- `mode==="timeout"`（未回答のままタイムアウト）は「あなたの回答: (未回答)」と表示する。
- 正解の選択肢には常に✓アイコンまたは緑文字を添え、一覧内でも「どれが正解だったか」が一目で分かるようにする（12.3の正誤フィードバック表示と視覚的に統一）。

### 17.3 「間違えた問題だけ再挑戦」ボタン
- 押下すると、復習対象だった問題（`records`で`score<1`だったもののみ）を新しい出題キューとして`appState="quiz"`に戻る（14.4節参照）。
- 再挑戦セッションであることが分かるよう、ヘッダーに「復習モード（3問中1問目）」のような専用ラベルを表示し、通常セッションのタイマー・進捗バーとは見た目上区別する（例: ヘッダー背景に薄いアクセント色の帯を1本加える程度の最小限の差別化でよい）。
- 再挑戦セッションにはタイマーを設けない（8分制限は既に消化済みのため）。ただし4択＋△ボタンの採点フローとサウンドは通常時と同様に動作させる。
- 再挑戦の結果は元のHR記録用`records`・結果画面のスコアには一切影響しない（17.2冒頭および14.4節の方針を再掲・徹底）。再挑戦終了後は「復習セッション終了（3問中2問正解）」等の簡易サマリーを出し、「結果画面に戻る」導線で締める。
