# 社内研修クイズWebアプリ 設計仕様書

対象: VR/アミューズメント業界社内研修クイズ（単一HTMLファイル・外部依存なし）
作成: デザイン担当エージェント
参考サイト調査結果: 後述「0. 参考サイト調査」参照

---

## 0. 参考サイト調査

参考URL `https://www.eigo-duke.com/tango/TOEIC1-1000.html` にWebFetchでアクセスし、以下の特徴を確認した。

- **配色**: 白背景＋黒文字を基調にした「清潔感のあるデザイン」。アクセントカラーに青系をボタン・リンクに使用。
- **フォント**: sans-serif系の読みやすい書体。見出しと本文でサイズ・階層を明確に分離。
- **表示形式**: フラッシュカード形式と単語帳（一覧表）形式を切り替え可能。一覧表は「No / 音 / 英語 / 日本語」の4列テーブル。
- **雰囲気**: 装飾を最小限に抑え、余白を適度に取った「シンプルで機能的」なデザイン。学習という目的に集中させる設計思想。

本仕様書では、この「シンプル・高コントラスト・余白重視・青系アクセント」の方向性を踏襲しつつ、タイマー・採点ボタンなど研修クイズ特有のUIをカード中心のレイアウトで追加する。

### 1.3 補足ルール
- タイマーはスタート画面の「はじめる」ボタン押下と同時に起動し、以後は一時停止・リセット不可（セッション全体で1本のカウントダウン）。
- ブラウザリロード時はステートを保持しない（研修の性質上、単純化のためlocalStorage等の永続化は行わない設計とする。必要であれば拡張検討項目として後述）。
- 結果画面から「もう一度」などのやり直し導線は本要件には無いため、原則として結果画面が最終到達点。ただし実装上は任意でスタート画面に戻る小さなリンクを置いてよい（人事評価記録後の次利用者への引き継ぎのため）。

### 3.3 実装方針
- CSS変数（`:root { --bg: ...; --text: ...; }`）を定義し、`@media (prefers-color-scheme: dark)`でオーバーライド。
- 手動切り替えトグルは必須要件ではないが、実装が容易なため画面右上に「☀/🌙」の任意トグルを置いてよい（OS設定を初期値とし、ユーザー操作でクラス切り替え）。
- コントラスト比はWCAG AA（通常テキストで4.5:1以上）を満たす組み合わせのみ採用。上記配色は全て背景/テキストの組でAA基準を満たすよう選定。

### 3.4 フォント方針
- OS標準のsans-serif系フォントスタックを使用し、Webフォント読み込み（外部依存）は行わない。
  ```
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Kaku Gothic ProN",
               "Hiragino Sans", Meiryo, sans-serif;
  ```
- 見出し（画面タイトル）: 20〜24px, bold
- 問題文: 18〜20px, 通常〜太字、行間1.6〜1.8で可読性重視
- 正解表示: 問題文よりやや大きく強調（色をアクセント寄りにするか、ラベル「正解:」を太字にする）
- ルール説明・注釈: 14〜15px
- タイマー数字: 24〜32px, 等幅ライクな見た目にするため`font-variant-numeric: tabular-nums;`を指定（桁のガタつき防止）
- ボタン内テキスト: 16px前後、タップ領域確保のため`padding`を十分に取る（後述アクセシビリティ参照）

## 4. インタラクションフロー（詳細状態遷移）

### 4.1 内部状態（State）定義

```
appState:
  "start"   … スタート画面表示中
  "quiz"    … 問題文表示、「答えを見る」待ち
  "answer"  … 正解表示、採点ボタン待ち
  "result"  … 結果画面表示中

currentIndex: 0..16   （現在の問題インデックス、全17問）
timeRemaining: 480 → 0 （秒、8分=480秒からカウントダウン）
records[]: 各問題ごとの { index, question, score(0/0.5/1/null), answered(bool) }
totalScore: records の score 合計（未回答は0として計算）
```

### 4.2 イベントと遷移

| 現在状態 | イベント | 遷移先 | 副作用 |
|---------|---------|--------|--------|
| start | 「はじめる」クリック（氏名あり） | quiz (index=0) | タイマー開始(480秒)、records初期化 |
| start | 「はじめる」クリック（氏名空） | start（変化なし） | エラーメッセージ表示 |
| quiz | 「答えを見る」クリック | answer | 正解テキスト表示、採点ボタン活性化 |
| answer | 採点ボタン（1/0.5/0点）クリック | quiz (index+1) または result | records[index]更新、progress更新 |
| quiz/answer | timeRemaining が 0 に到達 | result | タイマー停止、未回答分を0点・(未回答)で確定 |
| any (quiz/answer) | 最終問題(17問目)採点完了 | result | タイマー停止 |

### 4.3 タイマーとの競合処理
- タイマーの`setInterval`（1秒ごと）は`appState`が`result`になった時点で必ず`clearInterval`する。
- ユーザーが採点ボタンを押す操作とタイマーの0到達が同時に近いタイミングで発生した場合、**タイマー側の強制遷移を優先**し、以後のボタン操作は無視する（ボタンをdisabledにする、または遷移後はDOM自体が破棄される設計でも可）。

## 5. タイマーロジック仕様

### 5.1 基本仕様
- 初期値: **480秒（8分）**
- 起動タイミング: スタート画面の「はじめる」ボタン押下時に1回だけ`setInterval(tick, 1000)`を開始
- `tick`関数: `timeRemaining -= 1` → 表示更新 → `timeRemaining <= 0` なら結果画面へ強制遷移
- 表示形式: `MM:SS`（例: 480秒→`08:00`、59秒→`00:59`）。分・秒それぞれ2桁ゼロパディング。

### 5.2 警告閾値
- **閾値: 残り60秒（1分）未満、すなわち `timeRemaining <= 59`**
- 警告発火時の視覚変化:
  - タイマー文字色を警告色（ライト`#DC2626`／ダーク`#FCA5A5`）に変更
  - タイマー背景に警告用の淡い背景色を付与（ライト`#FEE2E2`／ダーク`#3F1D1D`）
  - 任意でCSSアニメーション（例: 1秒周期のopacity脈動 `0.7↔1.0`）を追加。ただし`prefers-reduced-motion: reduce`が指定された環境ではアニメーションを無効化し、色変化のみに留める。
- 警告状態は残り60秒から0秒まで継続。一度警告状態になったら解除されない（値が増えることはないため）。

### 5.3 タイムアウト時の挙動
1. `timeRemaining`が0に到達した瞬間、`setInterval`を`clearInterval`で確実に停止する。
2. 現在`appState`が`quiz`または`answer`のいずれであっても、即座に`appState = "result"`へ遷移する。
3. 未回答の問題（現在表示中の問題を含む、以降全て）は`records[i].answered = false`, `score = 0`として確定する。
4. 結果画面には「制限時間により終了しました」等のメッセージを結果ヘッダー付近に補足表示してもよい（必須要件ではないが推奨）。
5. タイムアウト後にタイマー表示自体は結果画面には表示しない（結果画面はスコアと内訳が主役）。

### 5.4 全問終了時の挙動
- 17問目（最終問題）で採点ボタンが押された場合、次の問題インデックスが存在しないため、タイマーの残り時間に関わらず即座に`clearInterval`し`result`へ遷移する。

## 6. 採点ロジック仕様

### 6.1 得点定義
| ボタン | 得点 | 意味 |
|-------|------|------|
| 正解（1点） | 1.0 | 口頭回答が正解と一致・十分に近い |
| 一部正解（0.5点） | 0.5 | 正確な答えは分からないが、わかる範囲のことを発言した場合 |
| 不正解（0点） | 0.0 | 無回答または誤答 |
| （未回答・タイムアウト） | 0.0 | システムが自動付与、ユーザー操作なし |

### 6.2 計算式
```
満点 (maxScore) = 問題数 × 1点 = 17 × 1 = 17.0点
合計スコア (totalScore) = Σ records[i].score  (i = 0..16)
正答率 (percentage) = round(totalScore / maxScore × 100, 1)  // 小数点1桁まで
```
- 表示例: `12.5 / 17.0点`、`正答率 73.5%`
- 四捨五入は小数点第1位までとし、`Math.round(x * 10) / 10`のような方式で計算（浮動小数点誤差対策として、内部計算は0.5刻みの整数演算＝スコアを2倍して整数で保持し、表示時に÷2する方式を推奨）。

### 6.3 記録データ構造（内部）
```
records[i] = {
  index: i,
  question: string,       // 問題文（quizData[i].question）
  correctAnswer: string,  // 正解（quizData[i].answer）
  score: 0 | 0.5 | 1 | null,  // null=未評価（タイムアウト直前など）→ 結果集計時は0扱い
  answered: boolean        // ユーザーが採点ボタンを押したか
}
```
- 集計時、`score === null`のレコードは`0`として合計・表示（「(未回答)」ラベルを付す）。

## 7. 結果画面のHR記録用レイアウト詳細

人事評価の記録として使われる想定のため、**視認性・印刷可読性・改ざん困難な簡潔さ**を重視する。

### 7.1 必須表示項目
1. ヘッダー: 「研修クイズ 結果レポート」の固定タイトル
2. 受験者名（スタート画面で入力した氏名をそのまま表示）
3. 実施日（クイズ開始時のシステム日付を`YYYY-MM-DD`形式で自動記録・表示。ユーザー入力不可＝改ざん防止）
4. 合計スコア: `獲得点 / 満点`形式（例: `12.5 / 17.0点`）を大きく強調表示（カード内で最も目立つフォントサイズ、24〜32px程度）
5. 正答率（%、小数点1桁）
6. 回答内訳テーブル: 全17問について「問題番号／問題文（要約可）／採点結果」を1行ずつ表示。未回答は「(未回答)」を明記。
7. 次回予告メッセージ（固定文言）: 「次回はHADO、リトプラ、ARゴジラから出題します」

### 7.2 印刷レイアウト（`@media print`想定）
- 印刷時はタイマー・ボタン類など不要なUIを`display: none`にする（結果画面にはそもそもタイマー・採点ボタンは存在しないため主にヘッダーの装飾色・背景画像相当を簡略化）。
- 背景色はページ全体を白に、テキストは黒に統一（インクの節約・可読性）。ただしスコアの強調枠線は維持（罫線で表現）。
- 内訳テーブルは罫線（`border: 1px solid #000`相当）を明示し、白黒コピーでも列の区切りが分かるようにする。
- A4縦想定、余白は上下左右20mm程度をイメージしたパディング。
- ページ下部に「印刷日時」の自動挿入は必須ではないが、`受験者名 / 実施日`の組でユニーク性は確保されるため必須要件ではない。

### 7.3 コピー（テキスト選択）のしやすさ
- 結果画面全体はテキスト選択可能な通常のHTML要素で構成し、`user-select: none`は使用しない（人事担当がコピー&ペーストで転記できるようにするため）。
- 受験者名・スコア・正答率をワンクリックでクリップボードにコピーする補助ボタン（任意、Clipboard APIが使えない環境向けに`document.execCommand`フォールバックまたは手動選択案内でも可）を検討してよいが必須ではない。

## 8. アクセシビリティ配慮点

1. **コントラスト比**: 全ての配色ペア（背景/前景）はWCAG AA基準（通常テキスト4.5:1以上、大きな見出し3:1以上）を満たす組み合わせを採用（3章の配色表参照）。
2. **キーボード操作**: 全てのボタン（開始・答えを見る・採点3種・印刷）は`<button>`要素で実装し、Tabキーでのフォーカス移動・Enter/Spaceでの実行が可能なこと。フォーカスリング（`:focus-visible`）を明示的にスタイルし、消さないこと。
3. **フォームラベル**: 受験者名入力欄には`<label for="...">`を明示的に紐付ける。
4. **状態変化の通知**: タイマー警告状態や画面遷移（quiz→answer→result等）は、スクリーンリーダー利用者向けに`aria-live="polite"`のリージョンで残り時間や採点結果を通知することが望ましい（例: 残り60秒を切った瞬間に一度だけ「残り時間が少なくなっています」と通知）。
5. **モーション配慮**: タイマー警告の点滅・脈動アニメーションは`@media (prefers-reduced-motion: reduce)`で無効化し、色変化のみで警告を伝える代替手段を確保する。
6. **タップ領域**: モバイル利用を考慮し、ボタンの最小タップ領域は44×44px以上を確保（特に採点3ボタンは横並びでも指で押しやすい間隔・サイズにする）。
7. **文字サイズ・拡大**: `rem`/`em`単位を基本とし、ブラウザのズーム・文字サイズ変更機能を妨げない（`user-scalable=no`をviewportに指定しない）。
8. **色だけに依存しない情報伝達**: 採点ボタン（正解=緑／一部正解=橙／不正解=赤）は色だけでなく、アイコン（✓/△/✗）とテキストラベル（「正解」「一部正解」「不正解」）を併記し、色覚特性に配慮する。
9. **見出し構造**: 各画面に適切な`<h1>`〜`<h2>`階層を設け、スクリーンリーダーでの画面把握を容易にする。
10. **言語属性**: `<html lang="ja">`を設定し、日本語コンテンツであることを明示する。

## 9. データ構造前提（実装引き継ぎ用メモ）

デザイン仕様は以下のデータ構造を前提とする（デザイン担当としてはこの構造を変更しないこと）。

```js
const quizData = [
  { question: "...", answer: "..." },
  // ... 全17問
];
```

- 問題数は固定値17として、進捗表示（`問題 X / 17`）・満点計算（17.0点）・プログレスバーの分母に用いる。
- 将来的に問題数が変動する可能性を考慮し、実装上はハードコードの`17`ではなく`quizData.length`を参照する設計を推奨（デザイン仕様としてもこの前提を明記しておく）。

## 10. 今後の拡張検討事項（本仕様のスコープ外・参考メモ）

- 結果データの外部保存（CSV出力、サーバー送信等）は本要件に含まれないため未設計。人事評価への反映は「画面印刷」または「目視転記」を前提とする。
- ライト/ダーク手動切り替えトグルの要否は実装フェーズで最終判断してよい（OS設定追従を基本線とする）。
- 複数受験者の連続実施（同一端末での使い回し）を想定する場合、結果画面から新規セッション開始への導線を追加検討する余地がある。
