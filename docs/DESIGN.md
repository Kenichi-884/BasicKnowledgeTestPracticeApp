# 設計ドキュメント インデックス(AIエージェント引き継ぎ用)

このディレクトリには、`vr_quiz.html`(社内研修クイズアプリ)の設計・仕様に関する全ドキュメントを格納しています。他のAIエージェント/開発者がこのプロジェクトを引き継いで拡張・保守する際は、まずこのファイルを読んでください。

## プロジェクト概要

- **目的**: VR/アミューズメント業界の社内研修クイズ(単一HTMLアプリ)。リモートメンバーも参加でき、口頭回答+自己採点/4択自動採点を組み合わせて実施する。
- **成果物本体**: `../vr_quiz.html`(単一HTMLファイル。外部ライブラリ・CDN・ネットワーク通信なし。ブラウザで直接開けば動作する)
- **現在のバージョン**: v2(4択形式+ひっかけ選択肢+サウンド+復習機能+ダークモード基調)

## ドキュメント構成と読む順序

1. `DESIGN_v1_base_spec.md` — v1(初期版)の設計仕様書。画面構成・状態遷移・タイマー仕様・採点仕様(自由回答+自己採点方式)・配色・アクセシビリティの土台。**現在は一部がv2で置き換わっているが、基本の画面構成・状態遷移の考え方は共通なので先に読むこと。**
2. `DESIGN_v2_addendum.md` — v2で追加された変更点の設計仕様(11章〜18章として追記)。以下を含む:
   - ダークモード基調への配色変更(具体的HEXコード)
   - 4択(1正解+3ひっかけ)+「△ 曖昧・一部正解(0.5点)」ボタンのUI設計
   - データ構造 `{ question, choices[4], correctIndex, ambiguousScore }`
   - Web Audio APIによる正解/不正解サウンドの合成方法
   - ライブ正答率表示、間違い復習機能のワイヤーフレーム
   - v1からの変更点対応表(18章)
3. `HIKKAKE_CHOICES_SOURCE.md` — 全17問分の「ひっかけ選択肢(誤答3つ)」の原本データ。`vr_quiz.html`内の`quizData`はこの内容を元に実装されている。**選択肢を差し替える場合はこのファイルの記述方針(妥当性のレベル、数値の近似のさせ方)を踏襲すること。**

## 実装済み機能(v2時点)

- 受験者名入力(必須)、実施日自動記録(改ざん防止のためユーザー入力不可)
- 8分(480秒)の全体カウントダウンタイマー、残り60秒未満で警告表示、0到達で結果画面へ強制遷移
- 17問・4択形式(選択肢はセッションごとにシャッフル、内部的にcorrectIndexを再マッピング)
- 4択クリックで自動採点(1点/0点)、「△ 曖昧・一部正解」ボタンで0.5点(口頭回答が曖昧だった場合用)
- 正解/不正解/△それぞれ異なる合成音(Web Audio API、外部音声ファイルなし)
- クイズ画面ヘッダーにライブ正答率表示
- 結果画面: 合計スコア/満点、正答率、内訳テーブル、次回予告(「次回はHADO、リトプラ、ARゴジラから出題します」)、印刷対応
- 間違えた問題(0点/0.5点)の復習一覧+再挑戦モード(タイマーなし、元スコア・記録には非干渉)
- ダークモード基調(デフォルト)+ライトモード切替トグル(localStorage保存)
- アクセシビリティ: label紐付け、aria-live、focus-visible、44px以上のタップ領域、lang="ja"

## 既知の設計判断・逸脱点(引き継ぎ時の注意)

- 4択の選択肢表示順はセッションごとにシャッフルされる(v1にはなかった仕様。v2追加仕様書で許容範囲として実装)。
- ライトモード時のタイマー警告色はv1の値(`#DC2626`/`#FEE2E2`)をそのまま踏襲(v2追加仕様にライトモード警告色の指定がなかったため)。
- 結果データの外部保存(CSV出力、サーバー送信、DB記録)は未実装。人事評価への反映は「印刷」または「画面の目視転記」を前提とする。複数人の結果を横断的に集計・管理したい場合はこの部分の追加設計が必要。
- 復習モード・再挑戦は同一セッション内のみで完結し、ページリロードで状態は失われる(永続化なし)。

## 次回の出題予定(拡張タスク)

結果画面に「次回はHADO、リトプラ、ARゴジラから出題します」という予告が既に表示されているが、**該当する問題データ自体はまだ`quizData`に含まれていない**。次にこのプロジェクトを引き継ぐ場合は、以下を追加実装すること:

1. HADO、リトプラ(リトルプラネット)、ARゴジラに関する問題文・正解を用意する(担当者へのヒアリングが必要)。
2. `HIKKAKE_CHOICES_SOURCE.md`と同じ方針で、追加問題ごとにひっかけ選択肢3つを作成する。
3. `vr_quiz.html`内の`quizData`配列に追記する(既存17問の構造`{ question, choices[4], correctIndex, ambiguousScore }`に合わせる)。
4. 満点・進捗表示は`quizData.length`を参照する実装になっているため、追加のみで自動的に反映される(コード側の改修は基本不要)。

## 拡張時に必ず確認すること

- `quizData`を変更した場合、`correctIndex`が`choices`配列内の正しいインデックスを指しているか必ず確認する(シャッフルロジックが`correctIndex`を前提に正誤判定するため、ズレると全問不正解扱いになるバグを引き起こす)。
- 新しい問題を追加・変更した際は、`node --check`でJS構文エラーがないか確認してからコミットする。
